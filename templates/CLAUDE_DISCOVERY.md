**MANDATORY READ: This file contains essential real-world scenarios for using CPM effectively throughout your development session.**

## 🎯 What is CPM?
The Claude Project Manager (CPM) is your **intelligent development assistant** that:
- **Tracks every function** in the project with enhanced detection (PHP, Python, JS/TS)
- **Maintains context** between conversations (resume exactly where you left off)
- **Monitors changes** in real-time (detect external modifications)
- **Provides project insights** (dependencies, complexity, progress, metrics)
- **Tracks refactoring operations** (function movements, file splits/merges)
- **Generates intelligent code** (functions, classes, tests, documentation)
- **Analyzes code quality** (complexity, maintainability, technical debt)
- **Accelerates development** (structured analysis + intelligent automation)

## 🏁 STEP 1: Initial Setup (Run These Commands First)

### 1. CPM Binary Detection & Setup
```bash
# Check for CPM installation
cpm --version

# Start CPM system (this includes context generation)
cpm start

# Start background monitoring daemon
cpm monitor --daemon

# CRITICAL: Check for pending tasks from previous sessions
cpm checkpoint list --json --limit=3
```

### 2. Load Project Context (Essential for Efficiency)

**⚠️ IMPORTANT FOR AI ASSISTANTS:**
The DIGEST.md file is generated by `cpm start` on first analysis. If it doesn't exist yet, use the AI-optimized alternative below.

```bash
# RECOMMENDED FOR AI: Use AI-optimized context (works even if DIGEST.md doesn't exist)
cpm ai-context --json --include-todos

# ALTERNATIVE: Read human-readable DIGEST if it exists
# Only use this if you're sure the file exists (after `cpm start` has completed analysis)
test -f .cpm/context/DIGEST.md && cat .cpm/context/DIGEST.md || echo "DIGEST.md not yet generated - use 'cpm ai-context --json' instead"

# ALWAYS read project-specific rules (this file always exists)
cat .claude.md
```

**Which command to use:**
- **First time / File missing**: `cpm ai-context --json --include-todos` (always works, AI-optimized)
- **DIGEST.md exists**: `cat .cpm/context/DIGEST.md` (human-readable format)
- **For structured data**: `cpm ai-context --json` (returns JSON, easier for AI to parse)

### Pattern 3: During Development
- **Let CPM track automatically** - daemon monitors all changes
- **Use TodoWrite** for progress tracking - CPM correlates with file changes
- **Check impact** before modifying key files

### Pattern 4: Session Handoff/Resume
```bash
# AI RECOMMENDED: Load previous session state with ai-context
cpm ai-context --json --include-todos --include-history

# CRITICAL: Check for pending tasks from previous sessions
cpm checkpoint list --json --limit=3

# ALTERNATIVE: Read DIGEST if it exists
test -f .cpm/context/DIGEST.md && cat .cpm/context/DIGEST.md

# Check incomplete work
cpm status --detailed | grep -E "(pending|in_progress)"

# Verify monitoring is active
cpm monitor --status
```

**⚠️ IMPORTANT**: Always check `cpm checkpoint list` at session start! Checkpoints may contain
pending tasks from previous sessions that need to be addressed.

| `cpm checkpoint create -d "description"` | Create a checkpoint with pending tasks | Session end, before handoff |
| `cpm checkpoint restore ID` | Restore a previous checkpoint | Resume previous session state |

### Progress Tracking Commands
| Command | Purpose | When to Use |
|---------|---------|-------------|
| `cpm progress mark-function ID --status=STATUS` | Mark function by ID | When you know the function ID |
| `cpm progress mark-range 51-62 --status=completed` | Mark range of IDs | Bulk updates (e.g., reviewed 10 functions) |
| `cpm progress mark-by-name "File.php:function" --status=STATUS` | Mark by name (no ID lookup!) | When you know file:function name |
| `cpm progress mark-complete FILE --reason="reason"` | Mark entire file complete | All functions in file done |
| `cpm progress show --json` | View progress status | Check completion percentage |
| `cpm progress validate` | Check data integrity | Troubleshooting |
| `cpm progress repair --auto-fix` | Fix schema issues | Auto-repair problems |

**Progress Status Values:**
- `pending` - Not started
- `in_progress` - Currently working on
- `completed` - Done
- `verified` - Reviewed and confirmed
- `has_issues` - Problems found

**Examples:**
```bash
# Mark by name (easiest - no ID lookup needed!)
cpm progress mark-by-name "Database.php:__construct" --status=completed --reason="Reviewed types"

# Mark range efficiently
cpm progress mark-range 51-62 --status=completed --reason="All reviewed"

# Mark with dry-run to preview
cpm progress mark-by-name "Logger.php:info" --status=completed --dry-run

# Mark by ID (traditional method)
cpm progress mark-function 78 --status=completed --reason="Fixed bug"
```
